# Документация IFDB REST API

REST API базы данных IFDB позволяет программно создавать, запрашивать, обновлять и публиковать игры, используя **канонический текстовый формат**, а также загружать файлы игр и прикреплять ссылки на скачивание.

Интерактивная документация (Redoc) доступна по адресу `/api/docs/`, а машиночитаемая спецификация OpenAPI 3.0 доступна по адресу `/api/openapi.json`.

---

## 1. Канонический формат описания игры (Canonical Format)

**Канонический формат** — это текстовое представление всех метаданных и описания игры, состоящее из двух частей:
1. **YAML Front Matter**: блок метаданных, заключённый между маркерами `---`.
2. **Markdown Body**: текст с описанием игры, расположенный после второго маркера `---`.

При сохранении игры через API движок (`games.gameinfo`) парсит документ, валидирует его, создаёт или связывает необходимые сущности (авторов, теги, ссылки) и сохраняет ревизию игры (`GameRevision`).

### Структура канонического документа

```yaml
---
- name: "Название игры"
- release_date: "2026-03-01"
- author:
  - ["Имя Автора"]
- translator:
  - ["Имя Переводчика"]
- tags:
  - ["genre", "Приключения"]
  - ["genre", "Фэнтези"]
  - ["os", "Windows"]
  - ["os", "Web (online)"]
  - ["control", "Парсерная"]
  - ["state", "Готовая"]
- urls:
  - ["download_direct", "Версия для Windows", "https://ifdb.example.com/f/uploads/games/42/game.zip"]
  - ["play_online", "Играть в браузере", "https://example.com/play/"]
  - ["game_page", "Страница на itch.io", "https://example.itch.io/game"]
- attributions:
  - ["Описание взято с сайта ifwiki.ru"]
---
Здесь начинается подробное описание игры в формате Markdown.

Поддерживаются:
* Списки
* **Жирный** и *курсивный* текст
* [Ссылки](https://example.com)
* Заголовки и цитаты
```

### Поддерживаемые поля Front Matter

#### Основные поля:
* `name`: Строка с названием игры.
* `release_date`: Дата релиза в формате `YYYY-MM-DD` или год `YYYY`.

#### Роли авторов и участников:
Каждая роль задаётся списком персоналий. Формат элемента: `["Имя"]` (или `[123] # "Имя"`, если используется числовой ID алиаса):
* `author`: Автор(ы) игры.
* `developer`: Разработчик(и).
* `editor`: Редактор(ы).
* `tester`: Тестировщик(и).
* `translator`: Переводчик(и).
* `artist`: Художник(и) / иллюстратор(ы).
* `musician`: Музыкант(ы) / композитор(ы).
* `voice`: Актёр(ы) озвучки.
* `special_thanks`: Особая благодарность.

#### Теги (`tags`):
Каждый тег задаётся парой `["категория", "название тега"]`:
* `genre` (Жанры): `Приключения`, `Фэнтези`, `Детектив`, `Хоррор`, `Юмор`, `Фантастика`, `Мистика`, `Драма`, `Сказка`, `18+` и др.
* `os` (Платформы): `Windows`, `Web (online)`, `Linux`, `MacOs`, `Android`, `iOS`, `DOS`, `Другая ОС`.
* `control` (Тип управления): `Парсерная`, `Менюшная`.
* `state` (Статус разработки): `Готовая`, `В разработке`, `Бета`, `Демо`.
* `tag` (Пользовательские теги): свободные метки.

#### Ссылки (`urls`):
Каждая ссылка задаётся кортежем `["категория", "описание/подпись", url_или_id]`:
* `download_direct`: Скачать (прямая ссылка на архив/файл игры).
* `download_landing`: Скачать (ссылка на файлообменник / внешнее хранилище).
* `play_online`: Играть онлайн в браузере.
* `game_page`: Страница игры на внешнем сайте (itch.io, Steam и т.д.).
* `forum`: Тема обсуждения на форуме.
* `review`: Обзор или рецензия.
* `video`: Видеообзор или прохождение на YouTube.
* `poster`: Постер / обложка.
* `screenshot`: Скриншот.

#### Источники описания (`attributions`):
* `attributions`: Список строк с указанием авторства текста описания (например, `["Википедия"]`, `["Журнал Навигатор"]`).

### Разрешение идентификаторов (ID Resolution)
При сохранении игры система автоматически привязывает строковые имена и URL к записям в базе данных. В возвращаемом каноническом документе ссылки и теги могут содержать числовые ID с комментариями для читаемости:
```yaml
- urls:
  - ["download_direct", "Архив 1.0", 351]  # "https://ifdb.example.com/f/uploads/games/42/game.zip"
```
При отправке новых правок через API можно передавать как строки с URL/именами, так и ранее разрешённые числовые ID.

## 2. Аутентификация и права доступа

Все запросы, изменяющие состояние данных, требуют токена авторизации. Создать токен администратор может в панели управления Django (`/adminz/api/apitoken/`).

### Заголовок запроса

Токен передаётся через стандартный HTTP-заголовок `Authorization`:

```http
Authorization: Bearer <ключ_токена>
```
или
```http
Authorization: Token <ключ_токена>
```

### Права и скоупы (Scopes)

Каждый токен привязан к учётной записи пользователя (`User`) и содержит список разрешённых прав (`permissions`). Если список пуст или содержит `*`, токену доступны все операции. Также можно ограничить токен отдельными правами:

* `games:read`: Чтение информации об играх и получение канонического текста.
* `games:write`: Создание и обновление игр.
* `games:publish`: Публикация и снятие с публикации, либо создание игры сразу в статусе `published`.
* `files:upload`: Загрузка файлов.

### Фиксация автора изменений

Все действия через API автоматически фиксируют владельца токена:
* `Game.added_by`: устанавливается в пользователя токена.
* `GameRevision.created_by` и `GameRevision.published_by`: устанавливаются в пользователя токена.
* `GameRevision.origin`: устанавливается в `API`.
* `URL.creator`: устанавливается в пользователя токена.

## 3. Эндпоинты

### Игры

#### `POST /api/v1/games/`
Создание новой игры.

* **Требуемый скоуп**: `games:write` (а также `games:publish`, если запрошено `state="published"`).
* **Статус по умолчанию**: `draft` (черновик).
* **Формат запроса**: JSON (`application/json`) или чистый текст (`text/plain`).

**Пример запроса в JSON**:
```json
{
  "canonical_text": "---\n- name: \"Таинственный Замок\"\n- release_date: 2026-04-10\n- author:\n  - [\"Иван Иванов\"]\n- tags:\n  - [\"genre\", \"Приключения\"]\n  - [\"control\", \"Парсерная\"]\n---\nУвлекательное текстовое приключение в старинном замке.",
  "state": "draft"
}
```

**Пример запроса в формате текста (`Content-Type: text/plain`)**:
```yaml
---
- name: "Таинственный Замок"
- release_date: 2026-04-10
- author:
  - ["Иван Иванов"]
- tags:
  - ["genre", "Приключения"]
  - ["control", "Парсерная"]
---
Увлекательное текстовое приключение в старинном замке.
```

**Ответ (`201 Created`)**:
```json
{
  "id": 15,
  "title": "Таинственный Замок",
  "state": "draft",
  "revision_id": 48,
  "canonical_text": "---\n- name: \"Таинственный Замок\"\n...",
  "created_at": "2026-09-05T16:00:00+00:00",
  "updated_at": "2026-09-05T16:00:00+00:00"
}
```

---

#### `GET /api/v1/games/<int:game_id>/`
Получение метаданных и канонического документа игры по ID.

* **Требуемый скоуп**: `games:read`.

**Ответ (`200 OK`)**:
```json
{
  "id": 15,
  "title": "Таинственный Замок",
  "state": "draft",
  "revision_id": 48,
  "canonical_text": "---\n- name: \"Таинственный Замок\"\n- release_date: \"2026-04-10\"\n...\n---\nУвлекательное текстовое приключение в старинном замке.",
  "created_at": "2026-09-05T16:00:00+00:00",
  "updated_at": "2026-09-05T16:00:00+00:00"
}
```

---

#### `PUT /api/v1/games/<int:game_id>/` (или `PATCH`)
Обновление метаданных и описания игры путём передачи обновлённого канонического текста.

* **Требуемый скоуп**: `games:write`.
* **Поведение**: Применяет изменения к полям игры, авторам, тегам, ссылкам и создаёт новую ревизию с `origin=API`.

**Тело запроса (`application/json`)**:
```json
{
  "canonical_text": "---\n- name: \"Таинственный Замок (Издание 2)\"\n- release_date: 2026-04-10\n- author:\n  - [\"Иван Иванов\"]\n---\nОбновлённое описание игры."
}
```

**Ответ (`200 OK`)**:
```json
{
  "id": 15,
  "title": "Таинственный Замок (Издание 2)",
  "state": "draft",
  "revision_id": 49,
  "canonical_text": "---\n- name: \"Таинственный Замок (Издание 2)\"\n...\n---\nОбновлённое описание игры.",
  "created_at": "2026-09-05T16:00:00+00:00",
  "updated_at": "2026-09-05T16:05:00+00:00"
}
```

---

#### `POST /api/v1/games/<int:game_id>/publish/`
Перевод игры из статуса черновика (`draft`) в опубликованный (`published`).

* **Требуемый скоуп**: `games:publish`.
* **Поведение**: Принимает и публикует последнюю ревизию игры, выставляет `state=published`. Идемпотентен.

**Ответ (`200 OK`)**:
```json
{
  "id": 15,
  "state": "published"
}
```

---

#### `POST /api/v1/games/<int:game_id>/unpublish/`
Снятие игры с публикации и перевод в статус черновика (`draft`).

* **Требуемый скоуп**: `games:publish`.
* **Поведение**: Переводит игру в статус `draft`. Идемпотентен.

**Ответ (`200 OK`)**:
```json
{
  "id": 15,
  "state": "draft"
}
```

### Загрузка файлов («Ссылка на скачивание»)

Поддерживаются два сценария загрузки:
1. **Отдельная загрузка**: загрузить файл заранее, получить его `url_id` и вставить в канонический текст перед созданием или редактированием игры.
2. **Загрузка с привязкой к игре**: загрузить файл непосредственно в карточку существующей игры. Файл автоматически помещается в директорию `games/<game_id>/`, регистрируется в базе как ссылка категории `download_direct` и сохраняется в новой ревизии игры.

---

#### `POST /api/v1/files/`
Отдельная загрузка файла.

* **Требуемый скоуп**: `files:upload`.
* **Content-Type**: `multipart/form-data`.
* **Параметры формы**:
  * `file`: бинарный файл.
  * `category` *(опционально)*: по умолчанию `"download_direct"`.
  * `description` *(опционально)*: подпись к ссылке (например, "Версия 1.0").

**Ответ (`201 Created`)**:
```json
{
  "url_id": 102,
  "url": "https://ifdb.example.com/f/uploads/castle.zip",
  "filename": "castle.zip",
  "canonical_snippet": ["download_direct", "", 102]
}
```
Значение `canonical_snippet` можно сразу вставить в блок `- urls:` вашего канонического документа.

---

#### `POST /api/v1/games/<int:game_id>/files/`
Загрузка файла с прямой привязкой к игре.

* **Требуемый скоуп**: `files:upload`.
* **Content-Type**: `multipart/form-data`.
* **Параметры формы**:
  * `file`: бинарный файл.
  * `category` *(опционально)*: по умолчанию `"download_direct"`.
  * `description` *(опционально)*: подпись к ссылке (например, "Релиз для Windows").

**Поведение**:
1. Файл сохраняется в хранилище по пути `games/<game_id>/<имя_файла>`.
2. Создаётся запись `URL` (`creator=пользователь_токена`, `is_uploaded=True`).
3. Создаётся связь `GameURL` с категорией `download_direct`.
4. Ссылка добавляется в канонический текст игры и создаётся ревизия с `origin=API`.

**Ответ (`201 Created`)**:
```json
{
  "game_id": 15,
  "url_id": 103,
  "url": "https://ifdb.example.com/f/uploads/games/15/castle_v1.zip",
  "filename": "castle_v1.zip",
  "category": "download_direct",
  "description": "Релиз для Windows",
  "canonical_snippet": ["download_direct", "Релиз для Windows", 103],
  "canonical_text": "---\n- name: \"Таинственный Замок\"\n- urls:\n  - [\"download_direct\", \"Релиз для Windows\", 103]\n---\n..."
}
```
